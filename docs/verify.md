# 에뮬레이터 확인 기록

환경: Pleos Connect v2.1.0 에뮬레이터 (API 34, 2560 × 1440, 160dpi), NaviHelper SDK 3.0.5, 내비 서비스 3.0.4.

## 2026-11-12 — 설치와 SDK 연결

| 확인한 것 | 결과 |
|---|---|
| debug APK 설치 | 성공 |
| `PlanActivity` 실행 | 성공. 화면 오른쪽 가로 두 칸에 표시됨 (왼쪽 한 칸은 차량 상태 화면) |
| `NaviHelper.initialize` | `onServiceConnected`, 서비스 버전 3.0.4 |
| `addListener` | 등록됨 (`registerCallbackV3`) |
| `getDestinationInfo()` | `onDestinationInfo` 콜백이 옴 |

### 내비에 목적지가 없을 때의 응답

`onError`가 아니라 **빈 값이 담긴 `DestinationInfo`** 가 온다.

```
DestinationInfo(latitude=0.0, longitude=0.0, name=, address=, remainDistance=0, remainTime=0, tollFare=0, poiId=, poiSubId=null, poiProvider=)
```

- `PlanActivity`는 이름이 비어 있으면 값을 버리고 JSON의 목적지(낙산해변)를 그대로 보여 준다. 그래서 내비에 목적지가 없어도 화면에는 목적지가 있는 것처럼 보인다.
- "목적지 없음"을 구분하려면 `name`이 비었는지 또는 좌표가 (0.0, 0.0)인지로 판단해야 한다.

### 목적지 없이 "안내 시작"을 눌렀을 때

내비에 목적지가 없는 상태에서 `removeWaypoint(ALL)` → `addWaypoint(...)`를 호출하면 `onError(CAUSE_SEARCH_ROUTE)`가 온다 (호출 후 약 0.15초).

- 경유지는 목적지(경로)가 있어야 넣을 수 있다.
- 앱은 이 오류를 로그로만 남기고 주행 화면(`DriveActivity`)으로 넘어간다. 경유지 등록이 실패해도 사용자는 알 수 없다.

### 화면 배치

`DriveActivity`가 세로 한 칸이 아니라 `PlanActivity`와 같은 오른쪽 넓은 영역에 떴다. 내비 옆 한 칸에 놓이는 배치는 아직 확인하지 못했다.

- "가장 가까운 도로"가 실제 주행 경로의 도로와 같은지는 확인하지 않았다 (오색약수터, 낙산사는 이름 없는 도로가 잡힘).

## 2026-11-12 — 경로 데이터 재검사 (`build_routes.py` 산출, 두 번째 판)

위 검사에서 나온 문제는 이 판에서 해소됐다: 문구 앞머리 없음, 한계령 좌표가 도로선 값으로 바뀜, 경유지 표시는 경로당 1곳, 두 테마 경로 모두 `verified: true`.

공개 OSRM으로 "서울 → 경유지 → 낙산해변" 경로를 직접 구해 대조했다.

| 경로 | 경유지 | OSRM 시간 | JSON `minutes` | 지점 ↔ 경로 거리 | 순서 |
|---|---|---|---|---|---|
| 산 | 한계령 | 188분 (204km) | 188 | 5곳 모두 0m | 맞음 |
| 바다 | 아바이마을 | 177분 (203km) | 177 | 5곳 모두 0m | 맞음 |
| 빠른 길 | 없음 | 151분 (182km) | 151 | — | — |

- 음성 9개가 `audioFile`과 일치하고 남는 파일이 없다. 5.5~8.7초.
- 바다 경로는 동해안을 따라 속초(아바이마을)까지 올라갔다가 같은 길로 내려온다. 그래서 대포항·속초해수욕장·물치해수욕장은 600m 안을 두 번 지난다. 안내는 순서대로 한 번씩만 나온다(대포항·속초는 올라갈 때 오른쪽, 물치·낙산사는 내려올 때 왼쪽).
- 산 경로의 흘림골·오색도 굽은 길 때문에 600m 안을 두 번 지난다. 두 번째에는 이미 다음 지점으로 넘어가 있어 다시 안내하지 않는다.
- 이 대조는 OSRM 기준이다. **Pleos 내비가 같은 길로 안내하는지는 에뮬레이터에서 확인해야 한다.** 특히 바다 경로는 내비가 속초를 고속도로로 먼저 가면 지점 순서가 어긋난다.

## 2026-11-12 — 에뮬레이터에서 화면 흐름 실행 (가짜 주행, 내비 목적지 없음)

`SIMULATE_DRIVE = true`, 밝은 화면. 화면 캡처와 로그로 확인했다.

| 확인한 것 | 결과 |
|---|---|
| 1. 목적지 확인 + 테마 선택 | 표시됨. "양양군 · 2시간 31분" |
| 2 → 3. 경로 찾기 → 경로 결과 | 산 3시간 8분 / 바다 2시간 57분 / 빠른 길 2시간 31분. 선택한 경로의 지점과 좌우가 펼쳐짐 |
| 5. 주행 화면 (접근 중) | "다음 설악산 장수대 · 오른쪽 · 900m", 지난 지점은 체크 표시 |
| 6. 안내 중 | "오른쪽 창밖" 띠 + 지점 이름 + 설명 문구가 한 번씩 |
| 들르기 버튼 | 들를 곳이 있는 지점에서 "한계령휴게소 들르기" 표시 (누르는 것은 미확인) |
| 산 경로 끝까지 | 5곳 순서대로 → "모든 곳을 지났습니다" |
| 바다 경로 끝까지 | 5곳 순서대로 → "모든 곳을 지났습니다" |
| 음성 | 지점마다 1회 재생. 출력 길이가 파일 길이와 일치 (산: 8.7 / 7.5 / 7.9 / 7.0 / 5.5초, 바다: 7.6 / 7.4 / 8.1 / 7.2 / 5.5초). 귀로 듣는 확인은 별도 |
| 앱 아이콘 | 앱 목록에 표시됨. 하단 바의 최근 앱 자리에는 기본 아이콘이 나옴 |
| 비정상 종료 | 없음 |

### 발견한 문제

1. **"안내 시작"을 누르면 내비 앱이 앞으로 올라와 주행 화면을 가린다.**
   `addWaypoint` 호출 직후 Pleos가 내비를 오른쪽 영역에 띄우고(목적지가 없으면 "경로를 얻지 못했습니다" 알림), 같은 자리에 있던 `DriveActivity`는 보이지 않게 된다. 주행 화면은 뒤에서 계속 돌아가고 음성도 나온다.
2. **`DriveActivity`가 내비 옆 한 칸이 아니라 내비와 같은 자리를 쓴다.**
   화면은 왼쪽 한 칸(853px, 차량 상태)과 오른쪽 넓은 영역(1682px)으로 나뉘고, 오른쪽에는 앱이 하나만 보인다. `screenOrientation` 미지정이어도 `DriveActivity`는 오른쪽 넓은 영역(`launchBounds 1682 × 1210`)을 받았다. 문서의 "미지정 = 세로 한 칸"과 다르다.
3. **하단 바에서 앱 아이콘을 누르면 주행 화면이 아니라 계획 화면이 새로 뜬다.**
   주행 중인 작업 위에 `PlanActivity`가 다시 쌓인다. 뒤로 가기를 누르면 주행 화면이 나온다.
4. 경로 결과의 지도 그림에서 지점들이 끝쪽에 겹쳐 보인다 (실제 지점이 모두 동쪽 끝에 몰려 있음).

## 2026-11-12 — 내비 연동 방식 변경

위 결과를 보고 연동 방식을 바꿨다.

- 이전: 사용자가 내비에 목적지를 잡아 둔 상태를 전제로 `removeWaypoint(ALL)` → `addWaypoint`. 목적지가 없으면 `CAUSE_SEARCH_ROUTE`로 실패했고, 확인할 때마다 이 전제에서 막혔다.
- 지금: "안내 시작"에서 `requestRouteWithWaypoints(목적지 + 경유지)`를 한 번 호출한다 (`NaviGateway.startRoute`). 경유지가 없는 빠른 길은 `requestRoute(목적지)`. 내비에 목적지가 없어도 된다.
- 목적지는 내비에 잡혀 있으면 그 값을, 없으면 경로 데이터의 목적지(낙산해변)를 쓴다.
- 들러보기는 그대로 `addWaypoint(2, …)`. 이때는 경로가 이미 있다.

화면 구성은 Pleos의 동작에 맞춘다: 안내 시작 후에는 내비가 오른쪽 영역을 쓰고, 앱은 뒤에서 음성 안내를 계속한다.

> 정정: 처음에는 "가려진 상태에서도 음성이 나오는 것을 확인했다"고 적었으나 틀렸다. 그때는 2초 안에 앱을 다시 앞으로 불러와서 멈추는 것을 보지 못했다. 아래 2차 실행 결과를 따른다.

**빌드와 단위 테스트만 통과했다. 에뮬레이터에서 아래를 한 번 확인해야 한다.**

- [x] `requestRouteWithWaypoints` 호출 후 내비가 한계령을 거치는 경로를 그리는가 (`onRouteStarted`, `onRoutingCompleted`)
- [x] `poiId`·`poiSubId`·`address`가 빈 문자열이어도 받아들이는가
- [ ] 바다 경로에서 내비가 동해안을 따라 속초까지 올라갔다 내려오는 길로 안내하는가

## 2026-11-12 — 2차 실행에서 나온 문제 (다른 PC)

1. **안내 시작 후 약 4초 뒤 앱 프로세스가 동결된다.**
   내비 앱이 앞으로 나와 주행 화면을 가리고, 4초 뒤 시스템이 Roadio 프로세스를 얼려서 안내와 음성이 멈췄다. 앱을 다시 앞으로 불러오면 그때부터 이어졌다.
   → 대응: 위치 판정과 음성을 화면(`DriveActivity`)에서 포그라운드 서비스(`GuideService`, 유형 `mediaPlayback`)로 옮겼다. 화면은 서비스의 상태만 보여 준다. **빌드와 단위 테스트만 통과했고, 실제로 동결을 피하는지는 에뮬레이터에서 확인해야 한다.** Pleos가 자체 기준으로 앱을 얼리는 것이라면 이 방법으로 안 될 수 있다.
   → 같이 고친 것: 안내 중에 하단 바에서 앱을 다시 열면 계획 화면이 아니라 주행 화면으로 간다.
2. **경로가 실제로 44번 국도·아바이마을 쪽으로 바뀌는지는 여전히 미확인.** 내비 지도가 비어 있고 목적지가 없었다. (이후 목적지와 경유지를 한 번에 요청하도록 바꿨다. 위 "내비 연동 방식 변경" 참고)
3. **에뮬레이터 첫 부팅 때 화면이 하얗거나 검게 나올 수 있다.** 차량 시스템 서비스(`vehiclecontrol`, `ai.pleos.hardware`)가 계속 죽는다. 에뮬레이터를 재부팅하면 정상이 된다. 앱과 무관하다.
4. **프로젝트 경로에 한글이 있으면 Android 빌드가 거부된다** (예: `공모전\현대 pleos`). 영문 경로에 두거나, 임시 드라이브로 연결해 빌드한다: `subst R: "한글이 든 경로"` → `R:`에서 빌드 → `subst R: /d`.

에뮬레이터에서 확인할 것:

- [x] 안내 시작 후 내비가 앞에 있는 상태로 1분 이상 두었을 때 음성이 지점마다 이어지는가
- [ ] 상단 알림에 "창밖 안내 중"이 뜨는가, 누르면 주행 화면이 열리는가
- [x] 안내 중에 하단 바에서 Roadio를 누르면 주행 화면이 지금 상태로 보이는가
- [x] 마지막 지점을 지난 뒤 약 30초 후 서비스가 내려가는가

## 2026-11-12 — 3차 실행: 경로 요청과 가려진 상태의 안내 (에뮬레이터)

내비에 목적지를 미리 잡지 않은 상태에서 산 경로로 확인했다. `SIMULATE_DRIVE = true`.

| 확인한 것 | 결과 |
|---|---|
| `requestRouteWithWaypoints(낙산해변 + 한계령)` | 받아들여짐. 약 10초 뒤 `onRouteStarted(duration=8280, distance=176000, tollFare=4690, name=한계령)` |
| 내비 화면 | 한계령을 경유지로 길 안내 시작. "2시간 18분 · 176km", 경로선과 회전 안내 표시 |
| `poiId`·`poiSubId`·`address` 빈 문자열 | 문제없이 받아들여짐 (좌표와 이름만으로 충분) |
| 목적지가 있을 때 `getDestinationInfo()` | `name=낙산해변, address=양양군 강현면, latitude=38.1236, longitude=128.6283, remainDistance=208000, remainTime=10800` |
| 내비가 앞에 있는 72초 동안의 안내 | 앱을 앞으로 부르지 않았는데 음성 5개가 지점 순서대로 모두 나옴 (8.7 / 7.5 / 7.9 / 7.0 / 5.5초). 프로세스 상태 `fg-service` |
| 안내 중 하단 바에서 앱 열기 | 주행 화면이 지금 상태로 열림 |
| 안내가 끝난 뒤 앱 열기 | 마무리 화면이 열림 (서비스는 내려간 뒤) |
| "내비게이션으로 돌아가기" | 주행 화면이 닫히고 내비가 앞에 남음 |
| 들르기 → `addWaypoint(2, 한계령휴게소)` | 오류 없음. 내비가 경로를 다시 찾고 `onWaypointChanged(index=FIRST, cmdType=ADD, name=한계령)` 응답 |
| 화면 | 밝은 화면 기본, 전환 버튼으로 어두운 화면, "준비 중" 테마, "+37분", 번호 지도, 한 줄 안내 띠, 마무리 화면 모두 표시 확인 |

알게 된 것:

- 경로 요청은 **이전 경로를 취소하고 새로 만든다**: `onRouteCancelled` → 빈 `onDestinationInfo` → `onWayPointInfo []` → 약 10초 뒤 `onRouteStarted`. `addWaypoint`도 같은 순서를 거친다.
- 내비가 계산한 경로(176km, 138분)는 경로 데이터의 값(204km, 188분)과 다르다. 출발지가 다르기 때문이다(에뮬레이터 현재 위치는 성남, 데이터는 서울시청).
- 들르기 응답의 `index`가 요청한 `SECOND`가 아니라 `FIRST`로 왔다. 한계령과 한계령휴게소가 둘 다 경유지로 남았는지는 확인하지 못했다.
